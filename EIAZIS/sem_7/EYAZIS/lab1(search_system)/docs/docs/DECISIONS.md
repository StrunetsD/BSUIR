# DECISIONS — архитектурные решения (ADR)

> Формат: контекст → решение → следствия. Новые ADR добавлять внизу.

---

## ADR-001 — Вариант 11 интерпретируем дословно

**Контекст.** Лаба 1.1 даёт матрицу вариантов. Выбран №11: интерфейс с
пользователем · локальная вычислительная сеть · вероятностная стратегия ·
английский язык.

**Решение.** UI — SPA на nginx (:8080, доступ по LAN); основная модель
ранжирования — вероятностная (BM25 как практическая реализация RSJ/BIM);
корпус, запросы и интерфейс — английские; TF-IDF (1.5–1.6) — индексация и
ключевые слова, как требует лаба.

**Следствия.** Dense/Hybrid — надстройки сверх обязательной части; в отчёте
основной моделью представлена вероятностная.

## ADR-002 — PostgreSQL + pgvector вместо Qdrant/Chroma

**Контекст.** Нужны и классический инвертированный индекс лабы (terms,
postings, веса), и векторный поиск.

**Решение.** Одна БД PostgreSQL 16 с расширением pgvector: реляционные
таблицы + колонка `vector(1024)` + HNSW-индекс.

**Следствия.** Плюс: одна транзакционная БД, наглядная ER-схема для отчёта,
pgadmin для демо. Минус: pgvector менее «экзотичен», чем выделенная ВБД —
принято осознанно ради простоты и целостности.

## ADR-003 — Mistral API основной LLM, Ollama — опциональный профиль

**Контекст.** Доступен ключ Mistral; на хосте GPU 4GB (крупные локальные
модели недоступны). Нужны: chat (RAG/expand/judge) и embeddings.

**Решение.** Провайдер абстрагирован (`LlmProvider`), по умолчанию mistral
(`ministral-14b-2512` — проверен владельцем, `mistral-embed` 1024d).
Ollama живёт в docker-профиле `local` (qwen2.5:3b + nomic-embed-text).

**Следствия.** Без ключа система полнофункциональна, кроме LLM-эндпоинтов
(503 с понятным сообщением). Размерность Ollama-эмбеддингов (768) паддинга-
ми добивается до 1024 нулями при записи в общую колонку (переключение
провайдера эмбеддингов после индексации требует реиндексации — warning в UI).

## ADR-004 — SQLAlchemy 2.x + psycopg (синхронно)

**Контекст.** Нагрузка учебная; важна простота и надёжность.

**Решение.** Синхронный SQLAlchemy 2 + psycopg3, FastAPI-роутеры — def-
функции (threadpool).

**Следствия.** Нет async-сложностей с pgvector; параллелизм достаточен.

---

## ADR-005 — Фронтенд: vanilla JS SPA без сборки

**Контекст.** Требование «самобытного» фронта и надёжного docker-пайплайна.

**Решение.** ES-модули + собственная дизайн-система (FRONTEND_RULES),
nginx отдаёт статику и проксирует /api. Chart.js — единственная зависимость
(локальная копия). Playwright-профиль для проверки.

**Следствия.** Нет node-сборки; весь внешний вид контролируется
дизайн-системой, а не шаблонами фреймворка.

## ADR-006 — Своя коллекция вместо Cranfield

**Контекст.** Метрики требуют qrels; демо должно быть читаемым.

**Решение.** 100 англ. документов, 8 тем, 15 запросов с градуированными
qrels — в репозитории, сидируются идемпотентно. Импорт Cranfield не делаем
(YAGNI); формат collection.json совместим с расширением.

---

## ADR-007 — BM25 = «вероятностная стратегия» варианта

**Контекст.** Лаба описывает вероятностную модель только теоретически (RSJ).

**Решение.** Реализуем RSJ-обоснование в отчёте, рабочий ранжер — Okapi BM25
(k1=1.2, b=0.75). Boolean и TF-IDF — базовые стратегии для сравнения по
метрикам, dense/hybrid — расширение.

---

## ADR-008 — Схема БД: DDL-скрипт вместо Alembic на старте

**Контекст.** Схема маленькая и стабильная; контейнер БД создаётся с нуля.

**Решение.** `backend/db/init.sql` через docker-entrypoint-initdb.d;
ORM отражает схему. Alembic вводим только если появятся миграции на живых
данных.

---

## ADR-009 — Порты

**Контекст.** Избежать конфликтов с локальными сервисами.

**Решение.** web **8080**, api **8000**, db **5433**→5432, pgadmin **5050**,
ollama **11434** (профиль local). Все бинды на 0.0.0.0 (требование LAN).

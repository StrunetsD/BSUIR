# AGENTS.md — правила работы ИИ-агентов с этим репозиторием

> Этот файл — точка входа для любой модели/агента, работающей с кодом проекта.
> Прочитай его ДО первого изменения кода. Незнание этих правил = брак.

## 0. Что это за проект

Лабораторная работа 1.1 «Разработка информационно-поисковой системы.
Реализация методов оценки качества ее работы» — **вариант 11**:
интерфейс с пользователем, локальная вычислительная сеть,
**вероятностная стратегия поиска**, **английский язык** коллекции и запросов.

Полная интерпретация: [docs/DECISIONS.md → ADR-001](docs/DECISIONS.md).
Карта документации: [README.md](README.md).

## 1. Порядок работы агента (обязательный ритуал)

1. Прочитай [docs/ROADMAP.md](docs/ROADMAP.md) — найди первый незакрытый этап.
2. Прочитай [docs/PROGRESS.md](docs/PROGRESS.md) — узнай, что уже сделано и есть ли «хвосты».
3. Прочитай специфику этапа: ссылки на документы лежат в ROADMAP рядом с задачами.
4. Работай строго в границах этапа. Не трогай будущие этапы «пока на будущее».
5. После каждого завершённого шага:
   - отметь чекбокс в ROADMAP;
   - добавь запись в PROGRESS.md (формат записи — в шапке этого файла журнала);
   - если принял проектное решение — добавь ADR в docs/DECISIONS.md.
6. Если обнаружил расхождение документ ↔ код, **документ — источник истины**,
   но если документ ошибочен относительно лабы (PDF) — истина PDF. Тогда:
   исправь документ и запиши причину в PROGRESS.md.

## 3. Конвенции кода

### Backend (FastAPI, Python 3.12)
- Python 3.12, типизация `typing`/`X | None` везде, Pydantic v2 для схем.
- SQLAlchemy 2.x + psycopg (синхронный драйвер) — см. ADR-004.
- Никаких секретов в коде: всё через `pydantic-settings` + `.env`
  (шаблон — `.env.example`). Файл `practice.py` в корне — черновик пользователя,
  его не импортировать и ключ из него не копировать.
- Структура пакетов: `backend/app/` — см. [docs/ARCHITECTURE.md §3](docs/ARCHITECTURE.md).
- Классы предметной области называть как в лабе: `Document`, `Search`,
  `SearchResult` (методы — см. [docs/ALGORITHMS.md §2](docs/ALGORITHMS.md)).
  Python-нейминг (snake_case), но семантика и поля — дословно из диаграмм PDF.
- Числа и ранжирование: `float` (double), никаких Decimal в скоринге.
- Каждая функция ранжирования и каждая метрика обязаны иметь unit-тест
  с hand-computed значением (см. этап 8 в ROADMAP).

### Frontend (vanilla JS SPA)
- Библиотек фреймворков НЕТ: чистые ES-модули, `Chart.js` — единственная
  сторонняя зависимость, хранится локально.
- Дизайн-система обязательна к исполнению: [docs/FRONTEND_RULES.md](docs/FRONTEND_RULES.md).
  Это не пожелание, а контракт: нарушение = переделка.
- Без сборки (no bundler): `index.html` + `assets/`, nginx отдаёт статику.

### Общее
- Комментарии в коде — только там, где «почему», а не «что».
- Формулы из лабы в коде сопровождаются ссылкой вида `# formula (1.5)` —
  это требование отчёта.
- Логи: `logging`, формат `%(asctime)s %(name)s %(levelname)s %(message)s`,
  без печати секретов.

## 4. Запрещено

- Коммитить `.env`, ключи, токены.
- Менять ports/routes/схемы БД без внесения правки в соответствующий .md
  (документ и код меняются одним коммитом/шагом).
- Использовать в UI: Inter/Roboto/Arial, Tailwind-палитры, эмодзи-иконки,
  градиентные баннеры, lorem ipsum — см. FRONTEND_RULES §8.
- Упрощать ранжирование до «придуманной» эвристики: только формулы из
  ALGORITHMS.md.
- Оставлять TODO без записи в PROGRESS.md.

## 5. Прогресс

Единственное место прогресса — [docs/PROGRESS.md](docs/ROADMAP.md) и
чекбоксы в [docs/ROADMAP.md](docs/ROADMAP.md). Прогресс никогда не пишется
в комментарии кода или README.

## 6. Как проверять себя

- Backend: `docker compose up --build api` + `pytest` внутри контейнера
  (этап 8 добавит Makefile-таргеты).
- Frontend: чек-лист FRONTEND_RULES §9 + Playwright smoke (этап 8).
- Системно: `docker compose up --build` поднимает всё одной командой;
  если поднялось, но «кажется, работает» — не считается: прогони сценарии
  из REPORT_CHECKLIST.md §3.
